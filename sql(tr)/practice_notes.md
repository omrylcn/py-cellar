## 1. PostgreSQL Temelleri ve Kurulum

### PostgreSQL Nedir?

PostgreSQL, açık kaynak kodlu, güçlü ve güvenilir nesne-ilişkisel veritabanı sistemidir. ACID uyumlu, gelişmiş veri türleri ve güçlü SQL desteği sunar.

### Kurulum (Ubuntu/Debian)

```bash
# PostgreSQL kurulumu
sudo apt update
sudo apt install postgresql postgresql-contrib

# Servis başlatma
sudo systemctl start postgresql
sudo systemctl enable postgresql

# PostgreSQL kullanıcısına geçiş
sudo -u postgres psql
```

### Temel Konfigürasyon

```sql
-- Yeni veritabanı oluşturma
CREATE DATABASE uygulama_db;

-- Yeni kullanıcı oluşturma
CREATE USER uygulama_user WITH ENCRYPTED PASSWORD 'güçlü_şifre';
GRANT ALL PRIVILEGES ON DATABASE uygulama_db TO uygulama_user;
```

### Temel psql Komutları

```sql
\l          -- Veritabanları listele
\dt         -- Tabloları listele
\d tablo    -- Tablo yapısını göster
\di         -- İndexleri listele
\q          -- Çıkış
```

## 2. Veri Türleri ve Özellikleri

### Sayısal Türler

```sql
-- Tam sayılar
SMALLINT    -- -32,768 to 32,767
INTEGER     -- -2 milyar to 2 milyar
BIGINT      -- Çok büyük sayılar

-- Ondalık sayılar
NUMERIC(10,2)     -- Kesin ondalık (para için)
REAL              -- 4 byte ondalık
DOUBLE PRECISION  -- 8 byte ondalık
```

### Metin Türleri

```sql
CHAR(n)       -- Sabit uzunluk
VARCHAR(n)    -- Değişken uzunluk (limit)
TEXT          -- Sınırsız metin
```

### Tarih ve Zaman

```sql
DATE                          -- Sadece tarih
TIME                          -- Sadece saat
TIMESTAMP                     -- Tarih + saat
TIMESTAMP WITH TIME ZONE      -- Zaman dilimi ile (önerilen)
INTERVAL                      -- Zaman aralığı
```

### PostgreSQL Özel Türleri

```sql
-- UUID
UUID DEFAULT gen_random_uuid()

-- JSON
```

## 3. Tablo Oluşturma ve ID Yapısı

### Temel Tablo Oluşturma

```sql
CREATE TABLE kullanicilar (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    kullanici_adi VARCHAR(50) UNIQUE NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    aktif BOOLEAN DEFAULT TRUE,
    kayit_tarihi TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

### PostgreSQL'de ID Oluşturma Yöntemleri

#### IDENTITY (PostgreSQL 10+ Önerilen)

```sql
-- Otomatik ID (manuel girişi yasak)
CREATE TABLE urunler (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    urun_adi VARCHAR(100) NOT NULL
);

-- Manuel ID girişine izin ver
CREATE TABLE kategoriler (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    kategori_adi VARCHAR(50) NOT NULL
);
```

#### UUID ile ID

```sql
-- UUID extension etkinleştir
CREATE EXTENSION IF NOT EXISTS "pgcrypto";

CREATE TABLE oturumlar (
    id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
    kullanici_id BIGINT NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

#### SERIAL (Eski Yöntem)

```sql
-- Artık önerilmez
CREATE TABLE eski_tablo (
    id SERIAL PRIMARY KEY,     -- INTEGER + sequence
    ad VARCHAR(50)
);
```

### ID Olmayan Tablolarda Sorunlar

#### ctid - PostgreSQL'in Fiziksel Row ID'si

```sql
CREATE TABLE test_tablo (
    ad VARCHAR(50),
    soyad VARCHAR(50)
);

-- ctid'leri görmek
SELECT ctid, ad, soyad FROM test_tablo;
-- Sonuç: (0,1), (0,2), (0,3)...

-- ⚠️ UYARI: ctid PRIMARY KEY değildir!
-- VACUUM sonrası değişebilir, güvenmeyin!
```

### ID Türü Seçim Rehberi

```sql
-- Küçük tablolar (< 32K)
SMALLINT GENERATED ALWAYS AS IDENTITY

-- Orta tablolar (< 2M)
INTEGER GENERATED ALWAYS AS IDENTITY

-- Büyük tablolar
BIGINT GENERATED ALWAYS AS IDENTITY

-- Distributed sistemler
UUID DEFAULT gen_random_uuid()
```

### Sequence Yönetimi

```sql
-- Sequence bilgilerini görme
SELECT last_value, increment_by FROM kullanicilar_id_seq;

-- Sequence'ı yeniden başlatma
ALTER SEQUENCE kullanicilar_id_seq RESTART WITH 1000;
```

## 4. Kısıtlamalar (Constraints)

### Primary Key

```sql
-- Tablo oluştururken
CREATE TABLE musteriler (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    musteri_kodu VARCHAR(20) UNIQUE NOT NULL
);

-- Composite primary key
CREATE TABLE siparis_detaylari (
    siparis_id BIGINT,
    urun_id BIGINT,
    miktar INTEGER,
    PRIMARY KEY (siparis_id, urun_id)
);
```

### Foreign Key

```sql
CREATE TABLE siparisler (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    musteri_id BIGINT,
    
    CONSTRAINT fk_siparis_musteri 
        FOREIGN KEY (musteri_id) REFERENCES musteriler(id)
        ON DELETE CASCADE
        ON UPDATE CASCADE
);
```

### Unique Constraints

```sql
CREATE TABLE kullanicilar (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    kullanici_adi VARCHAR(50) UNIQUE,
    email VARCHAR(100) UNIQUE
);
```

### Check Constraints

```sql
CREATE TABLE urunler (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    fiyat NUMERIC(10,2) CHECK (fiyat > 0),
    stok INTEGER CHECK (stok >= 0),
    durum VARCHAR(20) CHECK (durum IN ('aktif', 'pasif'))
);
```

### Not Null Constraints

```sql
CREATE TABLE kullanicilar (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    kullanici_adi VARCHAR(50) NOT NULL,
    email VARCHAR(100) NOT NULL,
    aktif BOOLEAN NOT NULL DEFAULT TRUE
);
```

## 5. Veri Modelleme ve Tasarım Prensipleri

### Normalizasyon

#### Birinci Normal Form (1NF)

```sql
-- ❌ 1NF ihlali - Tekrarlayan gruplar
CREATE TABLE kotu_siparis (
    siparis_id INTEGER,
    urun1 VARCHAR(50),
    urun2 VARCHAR(50),
    urun3 VARCHAR(50)
);

-- ✅ 1NF'ye uygun
CREATE TABLE siparisler (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    musteri_id BIGINT
);

CREATE TABLE siparis_detaylari (
    siparis_id BIGINT REFERENCES siparisler(id),
    urun_id BIGINT,
    miktar INTEGER,
    PRIMARY KEY (siparis_id, urun_id)
);
```

#### İkinci Normal Form (2NF)

```sql
-- ❌ 2NF ihlali - Kısmi bağımlılık
CREATE TABLE kotu_detay (
    siparis_id BIGINT,
    urun_id BIGINT,
    urun_adi VARCHAR(100), -- Sadece urun_id'ye bağımlı
    miktar INTEGER,
    PRIMARY KEY (siparis_id, urun_id)
);

-- ✅ 2NF'ye uygun
CREATE TABLE urunler (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    urun_adi VARCHAR(100) NOT NULL
);

CREATE TABLE siparis_detaylari (
    siparis_id BIGINT,
    urun_id BIGINT REFERENCES urunler(id),
    miktar INTEGER,
    PRIMARY KEY (siparis_id, urun_id)
);
```

#### Üçüncü Normal Form (3NF)

```sql
-- ❌ 3NF ihlali - Geçişli bağımlılık
CREATE TABLE kotu_calisanlar (
    id BIGINT PRIMARY KEY,
    ad VARCHAR(50),
    departman_id INTEGER,
    departman_adi VARCHAR(50)  -- departman_id'ye geçişli bağımlı
);

-- ✅ 3NF'ye uygun
CREATE TABLE departmanlar (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    departman_adi VARCHAR(50) NOT NULL
);

CREATE TABLE calisanlar (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    ad VARCHAR(50) NOT NULL,
    departman_id INTEGER REFERENCES departmanlar(id)
);
```

### Temel İlişki Türleri

#### One-to-One

```sql
CREATE TABLE kullanicilar (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    kullanici_adi VARCHAR(50) UNIQUE NOT NULL
);

CREATE TABLE kullanici_profilleri (
    kullanici_id BIGINT PRIMARY KEY REFERENCES kullanicilar(id),
    ad VARCHAR(50),
    soyad VARCHAR(50)
);
```

#### One-to-Many

```sql
CREATE TABLE kategoriler (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    kategori_adi VARCHAR(50) NOT NULL
);

CREATE TABLE urunler (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    urun_adi VARCHAR(100) NOT NULL,
    kategori_id INTEGER REFERENCES kategoriler(id)
);
```

#### Many-to-Many

```sql
CREATE TABLE etiketler (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    etiket_adi VARCHAR(50) NOT NULL
);

CREATE TABLE urun_etiketleri (
    urun_id BIGINT REFERENCES urunler(id),
    etiket_id INTEGER REFERENCES etiketler(id),
    PRIMARY KEY (urun_id, etiket_id)
);
```

## 6. Temel Index Türleri

### Index Nedir?

Index, veritabanındaki verilere hızlı erişim sağlayan veri yapılarıdır.

### B-Tree Index (Varsayılan)

```sql
-- En yaygın index türü
CREATE INDEX idx_email ON kullanicilar(email);
CREATE INDEX idx_tarih ON siparisler(siparis_tarihi);

-- Composite index
CREATE INDEX idx_musteri_tarih ON siparisler(musteri_id, siparis_tarihi);
```

### Hash Index

```sql
-- Eşitlik sorguları için hızlı
CREATE INDEX idx_kod_hash ON urunler USING HASH (urun_kodu);

-- Sadece = operatörü için kullanılır
-- Replication'da sorunlu, dikkatli kullanın
```

### GIN Index (Generalized Inverted)

```sql
-- JSONB için
CREATE INDEX idx_ozellikler_gin ON urunler USING GIN (ozellikler);

-- Array için
CREATE INDEX idx_etiketler_gin ON makaleler USING GIN (etiketler);

-- Full-text search için
CREATE INDEX idx_baslik_gin ON blog_yazilari USING GIN (to_tsvector('turkish', baslik));
```

### GiST Index (Generalized Search Tree)

```sql
-- Geometrik veriler için
CREATE INDEX idx_konum_gist ON lokasyonlar USING GiST (konum);

-- Range types için
CREATE INDEX idx_tarih_aralik_gist ON etkinlikler USING GiST (tarih_araligi);
```

### SP-GiST Index (Space-Partitioned)

```sql
-- IP adresleri için
CREATE INDEX idx_ip_spgist ON access_logs USING SP-GiST (ip_address);

-- Quad-tree yapıları için
```

### BRIN Index (Block Range)

```sql
-- Büyük, sıralı tablolar için minimal index
CREATE INDEX idx_created_brin ON logs USING BRIN (created_at);

-- Çok az yer kaplar, range queries için etkili
```

## 7. İleri Index Teknikleri

### Partial Index

```sql
-- Sadece aktif kayıtlar için index
CREATE INDEX idx_aktif_kullanicilar ON kullanicilar (email) 
WHERE aktif = TRUE;

-- Son 30 günlük veriler için
CREATE INDEX idx_son_siparisler ON siparisler (created_at)
WHERE created_at >= CURRENT_DATE - INTERVAL '30 days';
```

### Expression Index

```sql
-- Büyük-küçük harf duyarsız arama
CREATE INDEX idx_email_lower ON kullanicilar (LOWER(email));

-- Tam ad birleştirme
CREATE INDEX idx_tam_ad ON kullanicilar ((ad || ' ' || soyad));

-- JSON field index
CREATE INDEX idx_marka ON urunler ((ozellikler->>'marka'));
```

### Unique Index

```sql
-- Unique constraint oluşturur
CREATE UNIQUE INDEX idx_unique_email ON kullanicilar (email);

-- Partial unique
CREATE UNIQUE INDEX idx_unique_aktif_email ON kullanicilar (email)
WHERE aktif = TRUE;
```

### Concurrent Index Creation

```sql
-- Production'da kesinti olmadan index oluşturma
CREATE INDEX CONCURRENTLY idx_concurrent ON buyuk_tablo (kolon);

-- Hata durumunda temizlik
DROP INDEX CONCURRENTLY idx_concurrent;
```

### Covering Index (Include)

```sql
-- PostgreSQL 11+
CREATE INDEX idx_covering ON siparisler (musteri_id, tarih) 
INCLUDE (toplam_tutar, durum);

-- Index-only scan imkanı
```

## 8. Index Optimizasyonu ve Monitoring

### Index Kullanım İstatistikleri

```sql
-- En çok kullanılan indexler
SELECT 
    schemaname,
    tablename,
    indexname,
    idx_tup_read,
    idx_tup_fetch
FROM pg_stat_user_indexes 
ORDER BY idx_tup_read + idx_tup_fetch DESC;
```

### Kullanılmayan Indexler

```sql
-- Hiç kullanılmayan indexler
SELECT 
    schemaname,
    tablename,
    indexname
FROM pg_stat_user_indexes 
WHERE idx_tup_read = 0 AND idx_tup_fetch = 0
  AND indexname NOT LIKE '%_pkey';
```

### Index Boyutları

```sql
-- Index boyutlarını görme
SELECT 
    schemaname,
    tablename,
    indexname,
    pg_size_pretty(pg_relation_size(indexrelid)) as index_size
FROM pg_stat_user_indexes 
ORDER BY pg_relation_size(indexrelid) DESC;
```

### Index Maintenance

```sql
-- Index yeniden oluşturma
REINDEX INDEX CONCURRENTLY idx_name;

-- Tüm tablo indexlerini yeniden oluşturma
REINDEX TABLE CONCURRENTLY table_name;

-- İstatistikleri güncelleme
ANALYZE table_name;
```

## 9. Query Optimizasyonu ve EXPLAIN

### EXPLAIN Kullanımı

```sql
-- Basit plan görme
EXPLAIN SELECT * FROM kullanicilar WHERE email = 'test@example.com';

-- Detaylı analiz
EXPLAIN (ANALYZE, BUFFERS, VERBOSE) 
SELECT u.kullanici_adi, COUNT(s.id)
FROM kullanicilar u
LEFT JOIN siparisler s ON u.id = s.musteri_id
GROUP BY u.kullanici_adi;
```

### Plan Okuma

```sql
-- Önemli metrikler:
-- Cost: Tahmini maliyet
-- Rows: Tahmini satır sayısı  
-- Width: Ortalama satır boyutu
-- Actual time: Gerçek süre (ANALYZE ile)
-- Buffers: Kullanılan buffer sayısı
```

### Yaygın Operasyonlar

#### Seq Scan vs Index Scan

```sql
-- Seq Scan (tablo taraması)
-- Küçük tablolarda normal
-- Büyük tablolarda yavaş

-- Index Scan
-- Seçici sorgularda hızlı
-- Index maintenance maliyeti var

-- Index Only Scan
-- En hızlı, sadece index kullanır
-- VACUUM gerekli
```

#### Join Algoritmaları

```sql
-- Nested Loop: Küçük tablolar için
-- Hash Join: Orta büyüklükte tablolar için  
-- Merge Join: Büyük, sıralı tablolar için
```

### Query Optimizasyon İpuçları

#### WHERE Clause Optimizasyonu

```sql
-- ✅ Seçici koşulları önce yazın
WHERE aktif = TRUE AND created_at > '2025-01-01';

-- ✅ Index kullanacak şekilde yazın
WHERE LOWER(email) = 'test@example.com';  -- expression index gerekli

-- ❌ Index kullanamayan ifadeler
WHERE email LIKE '%@gmail.com';  -- % ile başlayan LIKE
WHERE YEAR(created_at) = 2025;   -- Function wrapper
```

#### JOIN Optimizasyonu

```sql
-- ✅ Foreign key'lerde index olsun
CREATE INDEX idx_siparis_musteri ON siparisler (musteri_id);

-- ✅ JOIN koşullarında aynı veri türünü kullanın
WHERE s.musteri_id = u.id;  -- İkisi de INTEGER olmalı
```

#### LIMIT ve ORDER BY

```sql
-- ✅ ORDER BY kolonunda index olsun
CREATE INDEX idx_created_desc ON siparisler (created_at DESC);

-- ✅ LIMIT kullanarak sonuç kümesini sınırlayın
SELECT * FROM siparisler 
ORDER BY created_at DESC 
LIMIT 20;
```

### Performans Monitoring

```sql
-- Yavaş sorgular (log_min_duration_statement ayarı gerekli)
SELECT query, mean_time, calls 
FROM pg_stat_statements 
ORDER BY mean_time DESC 
LIMIT 10;

-- Tablo istatistikleri
SELECT 
    schemaname,
    tablename,
    n_tup_ins,
    n_tup_upd,
    n_tup_del,
    seq_scan,
    idx_scan
FROM pg_stat_user_tables 
ORDER BY seq_scan DESC;
```

## Özet ve Best Practices

### ID ve Primary Key

- Her tabloda mutlaka primary key bulunmalı
- IDENTITY türünü SERIAL yerine tercih edin
- Doğru ID boyutunu seçin (SMALLINT/INTEGER/BIGINT)
- ctid'e güvenmeyin

### Index Stratejisi

- WHERE, JOIN, ORDER BY'da sık kullanılan kolonları indexleyin
- Composite index'lerde sıralama önemli (seçici kolon önce)
- Kullanılmayan indexleri kaldırın
- ANALYZE'i düzenli çalıştırın

### Query Optimizasyonu

- EXPLAIN ile sorgu planlarını inceleyin
- Seçici koşulları WHERE'in başına yazın
- Index kullanacak şekilde sorgu yazın
- JOIN'lerde foreign key indexleri oluşturun

### Monitoring

- pg_stat_statements ile yavaş sorguları takip edin
- Index kullanım istatistiklerini kontrol edin
- Tablo ve index boyutlarını monitör edin
